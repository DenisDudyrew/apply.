# apply. — локальная панель откликов

React + TypeScript, FastAPI и живые обновления через SSE. Приложение подбирает вакансии системных и бизнес-аналитиков и отправляет отклики через авторизованный API hh.ru. Авторизация и отправка используют `hh-applicant-tool`.

## Запуск

Откройте **`start.command`**. Панель доступна по адресу [127.0.0.1:55015](http://127.0.0.1:55015). Ничего не отправляется до нажатия «Запустить отклики».

Требуется Python 3.12 или новее. Первый запуск устанавливает зависимости и Chromium, поэтому нужен интернет. Собранный интерфейс находится в `frontend/dist`; Node.js для его запуска не требуется. Если сборки нет, запуск предложит установить Node.js и соберёт её через npm.

Если двойной щелчок не работает, из папки проекта выполните:

```bash
bash start.command
```

В верхнем правом углу находится аккаунт. Введите телефон или почту hh.ru, затем код из SMS или письма. Пароль и регистрация собственного API-приложения не нужны. Коды вводятся только в локальной панели и не записываются в журнал.

## Экраны

- **Обзор:** подтверждённые отправки за сегодня и за всё время, пропуски, записи для проверки, прогресс текущего запуска и отсчёт паузы. Статистика за сегодня считается по Москве.
- **Вакансии:** последняя найденная подборка, поиск по вакансии или компании, ссылки на hh.ru.
- **История:** отправленные и пропущенные карточки, причины, фильтры, поиск и страницы результатов. Стрелка строки раскрывает подробности.
- **Настройки:** максимум откликов и правила обработки. Сохраняются на компьютере для следующих запусков.

«Только найти» обновляет подборку без отправки. «Запустить отклики» начинает реальную отправку. Максимум — от 1 до 1000 подтверждённых новых откликов за запуск, по умолчанию 1000. Это настройка приложения, а не обход ограничений hh.ru: фактический результат может быть меньше.

## Правила

- **Без анкет:** тесты и обязательные вопросы пропускаются. Если выключить, доступные ручные формы открываются в панели.
- **В своей стране:** страна расположения вакансии сравнивается со страной в выбранном резюме. При включённой настройке неизвестная страна также отправляется на проверку. При выключении иностранная вакансия передаётся в панель для ручного решения.
- **Спокойный темп:** паузы 30–60 секунд между карточками. Отсутствие капчи не гарантируется. При выключении применяется `pause_seconds` из `config.json`, не менее 3 секунд.

Шаблон из `letter.txt` добавляется только при обязательном требовании сопроводительного письма. Метки `{vacancy}` и `{company}` заменяются названием вакансии и компании.

Фильтр названий принимает системную, бизнес- и fullstack-аналитику, включая Senior/Lead. Соответствие всем требованиям вакансии автоматически не оценивается.

## Капчи и анкеты

Карточка «Нужно твоё участие» появляется над обзором. В ней можно ввести код, текст капчи или работать с изображением страницы hh.ru.

Для ручной страницы нажмите поле на изображении, введите текст под ним и нажмите «Вставить». Кнопки и варианты ответов на изображении тоже нажимаются. Есть прокрутка и клавиши для редактирования. После заполнения и отправки анкеты нажмите «Готово, продолжить».

Для браузерной капчи доступны «Отправить капчу» и «Другая картинка». При сообщении о неверном тексте используется штатное обновление картинки hh.ru, без перезагрузки вакансии. API-капча показывается отдельной картинкой и проверяется клиентом `hh-applicant-tool`. Ответы вводите вы; автоматическое распознавание отключено. Ответ от устаревшей формы не переносится в новую.

Chromium работает без отдельного окна при использовании панели. Обычные API-отклики не используют выбранное по умолчанию резюме браузера: ID резюме передаётся явно после проверки. Для ручных форм сайт может попросить дополнительный вход и проверку выбранного резюме.

## Остановка и защита от повторов

Остановка происходит при ближайшей проверке или перед следующим сетевым запросом. Уже выполняющийся запрос может завершиться раньше. Закрытие вкладки само по себе не останавливает процесс.

Каждая пара «резюме + вакансия» сохраняется в SQLite. Уже обработанные карточки не отправляются повторно. Статусы `pending`, `uncertain`, `review` и `stopped` тоже не повторяются автоматически.

Пустой ответ создания отклика с HTTP 201 или 204 считается подтверждением отправки. При потере ответа или неизвестном результате запуск останавливается с `uncertain`, без автоматического повторения POST. Лимит hh.ru или отказ доступа останавливает запуск со статусом `stopped`. Такие записи доступны через фильтр «Нужна проверка»: проверьте результат на самом hh.ru.

Нельзя одновременно запустить две отправки в одной панели; отдельные экземпляры также защищены файловой блокировкой. Для браузерных форм сохраняется прежняя проверка результата на странице сайта.

## Локальные данные

- `auth-profile/` — токены и cookie авторизации, каталог доступен только вашему пользователю;
- `browser-profile/` — отдельная сессия Chromium;
- `state.sqlite3` — журнал и защита от повторов;
- `report.json` — экспорт журнала;
- `candidates.json` — последняя подборка;
- `ui-settings.json` — параметры следующего запуска;
- `screenshots/` — снимки доставки и состояний для проверки;
- `timing-events.jsonl` — время попыток и появления капчи, без ответов на неё.

Данные не отправляются сторонним сервисам; сетевые операции авторизации и откликов выполняются на hh.ru. Не передавайте папки авторизации, журнал и снимки другим людям. «Отключить» удаляет локальные токены API; уже сохранённый вход в браузере может оставаться активным. Это не отзыв всех сессий аккаунта.

Веб-сервер слушает только `127.0.0.1`. Доступ к действиям и потоку обновлений защищён токеном локальной панели и проверкой источника. Сервер отдаёт только собранные файлы интерфейса, а не папку проекта.

## Разработка

```bash
# Собрать React-интерфейс
npm ci --prefix frontend
npm run build --prefix frontend

# Запустить Python-сервер
.venv/bin/python ui.py --no-open

# Разработка интерфейса: Vite с прокси к локальному серверу
npm run dev --prefix frontend

# Автоматические проверки без реальных откликов
.venv/bin/python -m unittest -q

# Полный браузерный сценарий на изолированных данных
.venv/bin/python tests/browser_smoke.py
```

При разработке через Vite используйте URL `http://127.0.0.1:5173`, чтобы источник запросов совпадал с локальным прокси. Производственная сборка работает на одном адресе с FastAPI.

Структура:

- `frontend/src/` — React, TypeScript, Tailwind и компоненты на Radix UI в стиле shadcn/ui;
- `server.py` — FastAPI, проверка запросов, SSE, чтение истории и подборки;
- `ui.py` — состояние запуска и взаимодействие с рабочим потоком;
- `hh_auth.py` — адаптер авторизации `hh-applicant-tool`;
- `api_apply.py` — отправка через API и ручные формы;
- `hh_apply.py` — поиск, журнал, командный режим и браузерный механизм;
- `test_*.py`, `tests/browser_smoke.py` — проверки.

Настройки поиска, регион, ID и название резюме находятся в `config.json`. `send_method: "api"` — основной режим; `"browser"` возвращает прежнюю отправку кнопками сайта. Командный запуск поиска: `.venv/bin/python hh_apply.py`. Отправка с выбранным максимумом: `.venv/bin/python hh_apply.py --send --limit 10`.

Авторизация зависит от стороннего клиента [hh-applicant-tool](https://github.com/s3rgeym/hh-applicant-tool) и может требовать обновления при изменениях hh.ru. Работодательские чаты после отклика приложение не отслеживает. Автоматического расписания нет.

## Desktop 0.1 — Windows и macOS

Бесплатная локальная версия для личной помощи друзьям. Приложение не размещается на сервере; GitHub используется для исходников и сборок.

- Окно Tauri с React-интерфейсом, локальный Python-движок внутри установщика.
- Профили: загрузка своих резюме, рекомендации hh.ru по выбранному резюме или поиск по ключевым фразам, дополнительный фильтр названий.
- Письма: отдельный шаблон на профиль, режимы «только обязательно», «с каждым откликом» и «не добавлять», подстановки `{vacancy}`, `{company}`, `{resume}`.
- Очередь сохраняется в `queue.sqlite3`. После закрытия приложения можно продолжить необработанные карточки. Запись, во время которой приложение закрылось, проверяется по локальному подтверждению: неизвестная доставка не повторяется автоматически.
- Капча API: две паузы по 10 минут с безопасным GET-запросом проверки. Успех GET не объявляется решением капчи: исходная операция может снова получить явный отказ. После двух пауз потребуется ручной ввод. Есть кнопка «Заполнить сейчас». Авторизация по коду сразу требует ручного подтверждения, без двадцатиминутной задержки.
- Обычные отклики не требуют Chromium. Браузер ручных анкет скачивается при первом использовании таких форм.

В desktop-версии данные находятся в пользовательской папке приложения (Application Support на macOS, LocalAppData на Windows), а токены — в Keychain / Диспетчере учётных данных Windows. В исходниках и установщиках нет резюме, токенов или истории разработчика. Существующая разработческая панель использует прежнюю папку данных, без автоматического переноса в desktop-приложение.

Закрытие native-окна останавливает движок и сохраняет очередь. Уже выполняющийся сетевой запрос может завершиться до выхода. Для чистого выхода предусмотрено ожидание завершения; неопределённая доставка остаётся для проверки.

### Первый запуск для друзей

1. Откройте последний успешный запуск [Desktop installers](https://github.com/DenisDudyrew/apply./actions/workflows/desktop.yml) и скачайте артефакт своей платформы. Для скачивания артефактов нужен вход в GitHub; они хранятся 30 дней.
2. Распакуйте ZIP. На Windows запустите установщик `*-setup.exe`; на Mac откройте DMG и перенесите Apply в «Программы». Python и Node.js устанавливать не нужно.
3. В Apply нажмите «Войти в hh.ru» и подтвердите вход своим кодом. У каждого человека собственная локальная сессия.
4. В настройках создайте профиль, загрузите свои резюме и выберите нужное. Настройте письмо и пропуск анкет.
5. Сначала проверьте подборку без отправки: этот режим только находит вакансии. После проверки запускайте отклики с выбранным максимумом, до 1000 за запуск.
6. При капче можно заполнить её сразу или дождаться двух пауз по 10 минут. Таймаут не гарантирует исчезновение проверки; затем потребуется ручной ввод.

После остановки сохранённую очередь можно продолжить. Неопределённая доставка требует проверки на hh.ru и автоматически не повторяется.

### Сборка установщиков

На целевой ОС нужны Node.js, Python 3.12+ и Rust stable. Это требования для сборки, а не для конечного пользователя.

```bash
python -m pip install -r requirements-build.txt
npm ci --prefix frontend
npm run build --prefix frontend
python scripts/build_desktop.py
python scripts/test_frozen.py
```

GitHub Actions `Desktop installers` собирает Windows x64, macOS Apple Silicon и macOS Intel. Готовые файлы находятся в артефактах запуска: `Apply-Windows-x64`, `Apply-macOS-Apple-Silicon`, `Apply-macOS-Intel`.

Первая итерация — неподписанная внешним сертификатом beta. macOS-сборка имеет локальную ad-hoc подпись, но не нотарификацию Apple; Windows-сборка не имеет коммерческого сертификата издателя. Система может запросить дополнительное разрешение на запуск. Автоматическое обновление в этой итерации не включено: новые установщики распространяются вручную.

Атрибуция и условия стороннего клиента находятся в `THIRD_PARTY_NOTICES.md` и исходных метаданных `hh-applicant-tool`, включённых без изменения в приложение.
